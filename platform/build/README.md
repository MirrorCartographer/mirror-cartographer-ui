# Sovereign Build Graph and Deterministic Execution Plane

## Surviving architecture

The Reader emits normalized source. The project build graph then defines every action, dependency, toolchain, input, environment variable, output, resource bound, and network permission. A project executor computes portable action keys and invokes a replaceable sandbox adapter.

The initial implementation uses Nix to provide the pinned toolchain closure and isolated build environment. The graph remains implementation-neutral so a later Bazel Remote Execution API adapter, Buildbarn, Buildfarm, or direct microVM executor can run the same admitted actions.

## Authority

GitHub Actions, Nix derivations, Bazel BUILD files, CI YAML, and remote-execution schedulers may express or invoke work. None is the canonical build authority. The canonical object is the project-owned graph plus source, policy, toolchain, dependency, and action digests.

## Determinism controls

- no network during build actions;
- fetching occurs separately through fixed-output, digest-verified intake;
- fixed locale, timezone, working directory, and `SOURCE_DATE_EPOCH`;
- explicit environment allowlist;
- declared inputs and outputs;
- host tools and host filesystem forbidden;
- ephemeral rootless workers;
- sandbox failure fails closed;
- two empty-cache builds in independent failure domains;
- byte equality required before release admission;
- diffoscope and quarantine on mismatch.

A hermetic action is not automatically reproducible. Timestamps, unstable archive ordering, random values, filesystem iteration, compression metadata, locale, and compiler behavior can still differ. Reproducibility is established only by independent rebuilding and comparing output bytes.

## Cache boundary

The cache is an acceleration mechanism, never artifact authority or reproducibility evidence. Cache objects are content-addressed, signed where required, and rehashed on retrieval. Read and write authority are separated. The system must rebuild with an empty cache and must test poisoned-cache rejection.

## Provenance

The executor emits action keys, materials, outputs, worker image, graph, and log digests. Provenance is generated by the builder control plane and signed outside the build action, preventing build code from forging its own release evidence.

## Build-versus-buy

### Own

Graph schema, action-key algorithm, environment policy, toolchain and dependency closure, executor adapter contract, reproducibility admission, evidence, and recovery.

### Replaceable

Nix/Lix, Bazel, Buildbarn, Buildfarm, BuildGrid, microVMs, container runtimes, workers, caches, and hosted CI.

### Not physically owned

CPU manufacture, microcode, compiler bootstrap history, firmware, facilities, power, storage hardware, internet transit, public DNS, and upstream source publication.

## Unproven production evidence

The prototype verifies deterministic graph semantics but is not yet a kernel-enforced sandbox. Production requires actual Nix or microVM isolation, two hardware/software-diverse builders, offline toolchain reconstruction, poisoned-cache injection, diffoscope mismatch triage, bootstrap-chain analysis, and real application byte-for-byte rebuilds.
