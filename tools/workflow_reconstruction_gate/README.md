# Workflow Reconstruction Gate

## Purpose

This gate prevents scientific, medical, veterinary, mechanistic-biology, neuroscience, longitudinal-health, HCI, and privacy-memory claims from entering reusable Mirror Cartographer discovery memory unless the claim preserves enough workflow evidence for an outside reviewer to reconstruct how the claim was produced.

The core design implication from the frontier scan is that scientific AI systems are moving away from answer-only evaluation and toward workflow-level evaluation: hypothesis route, tools, datasets, perturbations, privacy boundary, missingness, human checkpoints, falsification route, and next executable action.

## Actionable design implication

Mirror Cartographer needs a **Workflow Reconstruction Gate** before discovery-memory promotion.

A claim is not reusable simply because it is plausible, cited, or generated by a frontier model. It must carry a reconstructable workflow packet that states:

- source status
- claim status
- privacy status
- missingness
- revision reason
- implementation status
- evidence strength
- falsification route
- next executable action
- workflow trace
- tool/data/model boundaries
- human checkpoint
- blocked inferences

## Claim status

Discovery-memory evaluation criterion.

## Privacy status

Public-safe synthetic schema and fixtures only. No personal medical, veterinary, or private longitudinal health data is included.

## Missingness

Required field. Packets must explicitly say what evidence, modality, species, time range, privacy consent, or workflow step is missing.

## Revision reason

Prior gates captured pieces of claim safety. This gate adds a reconstruction requirement: a future human or agent must be able to audit why a claim exists, where it came from, what it cannot infer, and how to falsify it.

## Evidence strength

Moderate. The cited frontier work strongly supports workflow-level evaluation as a design direction, but this exact schema is a local engineering hypothesis requiring validation.

## Falsification route

The gate should be revised or rejected if reviewers cannot reconstruct the evidence-to-claim path from valid packets better than from ordinary notes, or if the required fields add friction without improving auditability, privacy safety, or reproducibility.
