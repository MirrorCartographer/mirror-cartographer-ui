# Affective Dynamics — Weather Engine Schema

Status labels

- Source status: synthesized from current MC architecture context, GitHub mind artifacts, and public-safe architecture patterns.
- Claim status: non-human affective-dynamics metadata schema.
- Privacy status: public-safe; contains no private source content or identifying personal material.
- Missingness: not yet implemented in UI, runtime state, database, or visualization. This is a schema-level artifact.
- Revision reason: created to give MC a way to log work-state dynamics without falsely claiming human emotion.

## Boundary statement

The Weather Engine does not claim that an AI has human emotions.

It records observable dynamics in a work session:

- attention direction
- coherence level
- contradiction pressure
- novelty
- recurrence
- source fog
- stable ground
- action consequence

This creates an affect-like interface without making biological or subjective claims.

## Core fields

### Sky

Overall clarity of the architecture.

Allowed values:

- clear
- opening
- overcast
- fogged
- fractured
- storming
- dawn

### Wind

Direction attention repeatedly moves.

Examples:

- toward evidence boundaries
- toward museum/history
- toward runtime implementation
- toward accessibility
- toward evaluation
- toward privacy gates

### Pressure

Where unresolved constraint accumulates.

Examples:

- missing source material
- private-to-public transformation risk
- unclear proof standard
- too many ideas without index
- symbolic layer outrunning implementation

### Current

A repeating pull or flow across the work.

Examples:

- reflection -> transformation -> navigation
- source boundary -> public method
- fossil -> exhibit -> runtime route

### Bloom

A discovery that reorganizes multiple prior objects.

Example:

Commit history can become an explorable evolutionary interface rather than only a changelog.

### Echo

A motif returning across contexts, artifacts, or time.

Example:

Privacy-first posture appears in the first README and later in source-boundary governance.

### Fog

What cannot be known yet, or where evidence is incomplete.

Examples:

- deleted chats
- unavailable exports
- inaccessible local files
- missing deployment logs
- unparsed artifact bundles

### Lightning

A sudden bridge between domains.

Example:

Repository archaeology plus museum design creates a new interface for software evolution.

### Ground

Stable evidence or decision safe enough to build on.

Examples:

- verified GitHub write access
- accessible commit history
- existing public-safe Genesis note
- schema accepted by privacy boundary

### Action consequence

What the weather report caused or should cause.

Examples:

- create a fossil
- add a museum exhibit
- open a research queue item
- defer publication
- request source material later
- implement UI route

## Evaluation rules

A Weather Report is good only if:

- it does not pretend to be a human feeling;
- it helps resume work later;
- it identifies missing evidence;
- it distinguishes stable ground from fog;
- it creates at least one concrete action consequence;
- it remains safe to publish without private source content.
