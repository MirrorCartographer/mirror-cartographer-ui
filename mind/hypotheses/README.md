# Hypotheses Ledger

Purpose: store original Mirror Cartographer ideas that are plausible but not yet proven, implemented, or externally calibrated.

A hypothesis is allowed to be creative. It is not allowed to pretend to be evidence.

Entry fields:

- Hypothesis ID:
- Statement:
- Origin layer: Inner formation / Pattern observation / Product need / Research adjacency
- Expected usefulness:
- Possible failure mode:
- Evidence needed:
- External calibration sources needed:
- Implementation path:
- Claim status:
- Privacy status:
- Confidence:
- Status: Proposed / Testing / Supported / Weakened / Rejected / Implemented

Required distinction:

- Felt truth: meaningful inside the system.
- Functional truth: useful in product behavior.
- Evidence truth: supported by external data or validated testing.

Do not collapse these into one claim.
