# Contradiction Attractor: Claim Boundary

Status labels

- Source status: synthesized from current GitHub mind artifacts, public README boundaries, public-safe file-library snippets, and current public research.
- Claim status: conceptual force note; not validated product behavior.
- Privacy status: public-safe abstraction only.
- Missingness: no runtime compiler, no evaluator dataset, no user testing.
- Revision reason: this pass identifies contradiction as the strongest attractor because MC must hold expressive meaning and public safety at the same time.

## Force

Contradiction is not a defect in MC. It is the pressure that creates the router.

The system fails if it collapses expressive language into sterile compliance.

The system also fails if it lets expressive language become public overclaim.

The correct move is compilation:

`expressive source -> invariant meaning -> allowed claim -> permissioned view -> visible diff`

## Product implication

Every strong MC artifact should show two things at once:

1. The meaning that survived.
2. The claim that was allowed.

## Design rule

Never publish the private original when a public-safe translation is enough.

Never erase the fact that translation occurred.
