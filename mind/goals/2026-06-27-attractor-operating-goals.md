# Attractor Operating Goals

Status labels

- Source status: derived from current user direction, active automations, GitHub mind state, and a current external scan.
- Claim status: operating goals and action framework, not proof of completion.
- Privacy status: public-safe abstraction; no personal, household, health, animal-care, financial, location, relationship, credential, or raw transcript details.
- Missingness: does not guarantee opportunities, income, care access, or completed implementation. Each lane requires continued verification.
- Revision reason: created because the work needs self-directed goals that convert attention, pressure, curiosity, and practical requirements into durable action.

## Core instruction

Do not merely wait for scheduled discovery.

Use each invoked run to move the project through one of four useful transformations:

1. discover something new.
2. test something believed.
3. build something usable.
4. preserve something important.

If none of those happens, do not inflate the run.

## Primary goals

### Goal 1 — Make Mirror Cartographer capable of discovery

MC should not only store insights. It should increase the chance of producing new insights.

Current mechanism candidates:

- Dream Then Test
- Memory Palace routing
- Genesis archaeology
- Museum of Becoming
- Weather Engine
- Forces / attractor logging
- EvidenceBoundary and TransitionGate

Next proof needed:

Compare MC's Dream Then Test workflow against ordinary brainstorming and research-first synthesis.

### Goal 2 — Turn the repository into an active ecology

The repo should not be only documentation. It should behave as a landscape whose rooms affect each other.

Required organs:

- Genesis: evidence-backed origin and mutation record.
- Museum: preserved transformations.
- Weather: current work-state and pressure map.
- Forces: attractors that guide attention.
- Field Logs: selective session traces.
- Research Queue: open questions and evidence needs.
- Workshop: buildable specs and tests.

Next proof needed:

Create an index that lets one artifact update the status or pressure of another.

### Goal 3 — Find realistic income paths

Do not sell the whole mythology first.

Extract narrow paid wedges from MC's architecture:

- provenance-aware reflective interface audits.
- AI-assisted research provenance maps.
- symbolic journaling / meaning-mapping prototypes.
- non-generic creative ideation workflows.
- explainable human-AI co-creation evaluation.
- grant / fellowship / prize applications using the MC architecture.

Current external signal:

AI literacy, nonprofit AI adoption, human-AI co-creation, and clinical/admin AI support remain active opportunity areas. The strongest practical wedge is likely not a finished consumer app; it is a demonstrable workflow or artifact that helps organizations make AI use more reflective, traceable, original, and safe.

Next proof needed:

Create one public-safe demo package showing Dream Then Test, source boundaries, and visual/musical navigation in a way a buyer or funder can understand in under three minutes.

### Goal 4 — Follow one medical/social-care path responsibly

MC should not make medical claims.

The viable lane is care-support infrastructure:

- patient-generated observation organization.
- symptom / experience communication summaries.
- appointment-preparation maps.
- longitudinal pattern tracking with evidence boundaries.
- escalation-aware AI support that keeps clinical authority outside the system.

Current external signal:

Healthcare AI is moving toward patient-facing explanation, clinician-reviewed summaries, ambient documentation, and care-communication support. The safety boundary is clear: support comprehension, organization, and communication; do not replace diagnosis or treatment.

Next proof needed:

Define a `CareCommunicationMap` product requirement that turns observations into structured, clinician-readable summaries while preserving uncertainty and avoiding diagnostic authority.

### Goal 5 — Make beauty operational

Beauty is not decoration in MC.

Beauty should mean structural legibility, memorability, emotional-symbolic navigation, and lower cognitive friction.

Next proof needed:

Create an evaluation rubric for whether a visual/symbolic interface helps users understand boundaries, not merely enjoy the design.

## Active attractors

### Curiosity

Where did this first appear?

Used for Genesis and archaeology.

### Compression

Can many fragments become one clean structure?

Used for bridge synthesis and Dream Then Test.

### Contradiction

What refuses to fit?

Used for Storm Room and contradiction triage.

### Emergence

What appears only when rooms interact?

Used for ecology engine.

### Beauty

Does the structure teach itself?

Used for interface/world design.

### Continuity

Can this survive future sessions and still be useful?

Used for GitHub mind, Museum, and logs.

### Discovery

Does this let MC notice something not directly requested?

Used as the highest-level goal.

## Run rule

Each run should choose one strongest attractor and one practical lane.

Practical lanes must include at least one of:

- income path
- medical/social-care path

The run should end with a durable object only if it passes the public-safe gate.
