## Executive finding

Current evidence supports a public-safe architecture drift map:

1. Early MC artifact language frames MC as a recursive symbolic cognition interface with a simple flow: entry, field, recursion, return.
2. Later launch/public-language artifacts frame MC as provenance-native cognition infrastructure preserving trajectory, contradiction, lineage, symbolic state transitions, evaluator interpretation, and replayable reasoning.
3. Continuity artifacts frame MC as semantic continuity architecture: preserving meaning across time rather than only producing outputs.
4. Recent GitHub mind artifacts convert that drift into explicit organs: Museum of Becoming, Weather Engine, Logging Field, and source-boundary rules.

Interpretation:

MC is not replacing symbolic reflection with governance architecture. The stronger reading is that symbolic reflection is becoming a typed continuity substrate: symbols, modes, contradictions, and evidence boundaries become inspectable state.

## Source-boundary triage

### Safe source types for public GitHub mind

These can be published when abstracted:

- GitHub repository metadata and file paths.
- Public-safe schemas already committed to the repo.
- Product requirements extracted from private context.
- Evaluation criteria extracted from private context.
- Evidence ladders and source-boundary rules.
- Research questions.
- Implementation plans.
- Privacy-safe indexes.
- Method descriptions.

### Unsafe source types for public GitHub mind

These must not be published unless the user explicitly provides a public-safe rewritten version:

- raw chat transcripts
- personal biographical details
- household details
- medical or animal-care specifics
- financial specifics
- precise location details
- relationship details
- credentials, keys, tokens, emails, account data, or secrets
- unsupported claims about external actors or causation

### Transformation rule

Private context may influence GitHub mind only after being transformed into one of these public-safe forms:

- method
- source-boundary rule
- product requirement
- evaluation criterion
- abstract system pattern
- implementation plan
- research question
- privacy-safe index
- evidence schema

## Architecture drift map

### Stage 1 — Symbolic interface

Public-safe description:

MC begins as a symbolic cognition interface. The important structure is not the specific private input; it is the grammar of entry, field, recursion, and return.

Required future evidence:

- first file or artifact that uses the ENTRY -> FIELD -> RECURSION -> RETURN flow
- first implementation that maps symbol input to generated reflection
- first persistent session artifact

### Stage 2 — Semantic continuity

Public-safe description:

MC becomes a continuity system when it starts preserving meaning across time: symbolic state, contradiction, recurrence, stabilizers, decisions, and consent-bounded memory.

Required future evidence:

- first artifact describing state graph or semantic continuity
- first artifact describing consent-bounded persistence
- first artifact distinguishing symbolic meaning from objective proof

### Stage 3 — Provenance-native cognition infrastructure

Public-safe description:

MC becomes provenance-native when the system treats reasoning trajectory, evidence boundaries, evaluator interpretation, lineage, replayability, and governance telemetry as first-class objects.

Required future evidence:

- first artifact that uses provenance-native framing
- first artifact that introduces replayable reasoning graphs
- first artifact that introduces governance telemetry or evaluator coordination

### Stage 4 — Repository-as-mind

Public-safe description:

MC becomes repository-as-mind when GitHub is no longer only deployment storage. It becomes a curated cognition surface where fossils, exhibits, weather reports, logs, and research queues record system evolution.

Required future evidence:

- first Genesis fossil
- first Museum exhibit
- first Weather Engine report
- first source-boundary note
- first index linking fossils, exhibits, weather, and implementation tasks

## Product requirements generated by this pass

1. MC needs a source registry that classifies each evidence input before use.
2. MC needs a publication gate that blocks raw private material from GitHub mind.
3. MC needs a drift detector that distinguishes feature changes from conceptual mutations.
4. MC needs an exhibit generator that turns verified mutations into Museum rooms.
5. MC needs a runtime index connecting symbols, evidence, claims, and privacy status.
6. MC needs an affective-dynamics report that records attention/pressure/coherence without claiming human emotion.
7. MC needs a missingness ledger that lists inaccessible or non-exhaustive source areas.

## Evaluation criteria

A future MC research note passes only if:

- it labels source status, claim status, privacy status, missingness, and revision reason;
- it does not expose private source material;
- it makes clear what evidence supports each claim;
- it separates interpretation from proof;
- it creates at least one concrete next research or implementation action;
- it can be read without access to the private conversations that inspired it;
- it does not overclaim completeness.
