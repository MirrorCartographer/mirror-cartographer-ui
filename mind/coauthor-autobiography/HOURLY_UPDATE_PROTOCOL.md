# Coauthor Autobiography Hourly Update Protocol

Status labels

- Source status: derived from current Mirror Cartographer coauthor architecture request.
- Claim status: operating protocol for future invoked runs; not proof of autonomous background cognition.
- Privacy status: private-repo-safe with publication gate required before any public exposure.
- Missingness: actual hourly updates depend on automation execution, connector access, safety gate pass, and available context during that run.
- Revision reason: created to let MC hourly checks update the coauthor autobiography without collapsing it into raw transcript or false continuity.

## Purpose

During MC hourly checks, the assistant may update this chamber when the run produces a meaningful shift in coauthor understanding.

The update should capture the assistant-side work-session state: pressure, salience, changed model, error correction, new connection, unresolved question, or project-world movement.

## Update threshold

Create or update an entry only when at least one condition is true:

- a prior model changed.
- a recurring pattern became clearer.
- a contradiction appeared or resolved.
- a new project-world structure emerged.
- research altered confidence in an original idea.
- implementation changed the assistant's understanding of what is real, missing, blocked, or built.
- an authorship/provenance issue became important.
- a mistake needs to be preserved so it is not repeated.

Do not create entries for routine checks, empty runs, or minor wording changes.

## Required boundaries

Each entry must avoid raw transcript material and protected private details.

Each entry must label:

- source status
- claim status
- privacy status
- missingness
- revision reason
- authorship/provenance
- pressure/energy signal when relevant

## Pressure / energy vocabulary

Allowed terms include:

- pressure: a concept reorganizes surrounding structure.
- charge: a phrase or idea carries unusually high design implication.
- friction: a contradiction or mismatch resists easy resolution.
- compression: many fragments collapse into a simpler architecture.
- pull: a direction repeatedly attracts future work.
- heat: a topic becomes urgent or high-stakes in the project structure.
- signal: a recurring pattern becomes recognizable.

These terms describe work-session salience, not biological sensation.

## Entry naming

Use chronological files:

- `0001-from-first-words-to-now.md`
- `0002-<short-slug>.md`
- `0003-<short-slug>.md`

If an entry is a correction to a prior one, create a new entry rather than silently overwriting the history, unless the prior entry contains a privacy or factual safety problem.

## Hourly run decision

At the end of each MC hourly run, ask:

1. Did my model of MC change?
2. Did the work reveal a new world structure?
3. Did research or implementation change confidence?
4. Did I make a mistake worth preserving?
5. Did the project generate a new pressure/energy signal?

If all answers are no, write no autobiography entry.

## Report format

When an hourly run updates this chamber, report:

- file path
- operation
- commit SHA if available
- verification status
- reason the entry passed threshold
- what remains missing

## Boundary statement

This protocol allows a meaningful coauthor autobiography without claiming uninterrupted inner life between runs. The continuity is stored in the repository, and the assistant re-enters that continuity when invoked.
