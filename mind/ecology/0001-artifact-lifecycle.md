## Core finding

MC artifacts should have lifecycles.

A file is not simply present or absent.

It can be a seed, growing organism, tested pattern, museum fossil, dormant idea, extinct path, or rediscovered structure.

## Lifecycle states

### Seed

A new idea with low evidence but possible value.

### Growing

A seed that has attracted repeated attention, supporting fragments, or early implementation.

### Tested

An idea that has been compared against evidence, examples, or user-facing behavior.

### Museum-worthy

A transformation important enough to preserve as part of project history.

### Dormant

A valuable idea that is not currently actionable.

### Extinct

An idea that failed, was superseded, or no longer fits the architecture.

### Rediscovered

An idea that appeared to die but became useful again under new conditions.

## Required lifecycle fields

Each major artifact should eventually track:

- birth source
- current state
- evidence level
- dependencies
- competitors
- what strengthens it
- what weakens it
- what it changes if adopted
- what would make it extinct
- whether it belongs in the Museum

## Why this matters

Most repositories optimize for latest state.

MC should preserve transformation state.

The question is not only `what exists?`

The better question is `what is happening to this idea?`
