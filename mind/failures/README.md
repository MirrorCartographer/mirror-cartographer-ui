# Failures Ledger

Purpose: preserve mistakes, dead ends, misleading frames, overclaims, weak artifacts, and rejected approaches so the project learns instead of repeating drift.

Failure is useful when it is specific.

Entry fields:

- Failure ID:
- What failed:
- Failure type: Privacy / Claim inflation / Interface / Architecture / Research / Implementation / Communication / Evaluation
- Why it failed:
- What it taught:
- What changed after:
- Related decision:
- Related experiment:
- Status: Active risk / Mitigated / Replaced / Deprecated

Important failure classes:

- Treating private context as publishable content.
- Calling a proposed artifact committed.
- Treating symbolic meaning as objective evidence.
- Building public research summaries without creating original MC architecture.
- Making outputs that are technically correct but emotionally/visually dead.
