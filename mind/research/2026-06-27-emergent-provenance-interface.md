## Core discovery

The next useful MC unit is not another document.

It is an `Emergent Provenance Interface`: a visible surface where meaning, source boundaries, translation paths, and practical next steps change together.

The repository already contains the pieces:

- Attractor Operating Goals: MC should discover, test, build, or preserve rather than merely store.
- Semantic Invariant Translation Protocol: meanings should be translated before words.
- Artifact Lifecycle Ecology: ideas should have lifecycle states rather than static file presence.
- Income Wedge Map: the first commercial wedge should be narrow, legible, and demonstrable.
- Care Communication Map: the responsible care lane is communication support, not diagnosis or treatment.

The emergent pattern is:

`a meaning-state should be navigable, bounded, translated, and testable at the same time.`

## Why this matters

Most AI transparency work focuses on output marking, source citation, or verification after a thing exists.

MC's distinct public-safe contribution can be earlier in the process:

- show how an idea changed before it became an output.
- show which domain lens changed the meaning.
- show what privacy or safety boundary transformed the wording.
- show which practical lane the idea now touches.
- show what test would make the idea stronger or weaker.

This makes provenance a user-facing cognition surface, not only a compliance record.

## Interface object

An Emergent Provenance Interface should show one idea as five synchronized layers:

1. Meaning layer: the invariant structure.
2. Word layer: the current vocabulary used to express it.
3. Boundary layer: source, claim, privacy, allowed use, blocked use, and missingness.
4. Lifecycle layer: seed, growing, tested, museum-worthy, dormant, extinct, or rediscovered.
5. Practical layer: income relevance, care/social-support relevance, research relevance, or no current practical lane.

## New rule

A translation is not complete until MC can show what changed across all five layers.
