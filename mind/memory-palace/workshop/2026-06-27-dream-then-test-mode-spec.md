# Workshop Spec — Dream Then Test Mode

Date: 2026-06-27

Status labels

- Source status: synthesized from forge, observatory, bridge, and mirror-room entries.
- Claim status: product specification and evaluation plan.
- Privacy status: public-safe abstraction.
- Missingness: not implemented in runtime; no user study completed.
- Revision reason: created to translate the first memory-palace research run into buildable behavior.

## Mode purpose

`Dream Then Test` is a Mirror Cartographer session mode for preserving original symbolic/product insight while later calibrating it against evidence.

## State machine

1. Dream
   - Generate from the project-world.
   - No external research yet.
   - Capture symbols, spatial structures, metaphors, product seeds, and pressure signals.

2. Label
   - Separate metaphor, design idea, hypothesis, observation, implementation claim, and evidence claim.

3. Research
   - Search external evidence only after the dream is legible.
   - Collect support, contradiction, prior art, adjacent language, and risk.

4. Bridge
   - Decide preserve, refine, split, test, park, or reject.

5. Build
   - Convert surviving structure into feature, protocol, test, document, or prototype.

6. Evaluate
   - Compare output against ordinary brainstorming and research-first brainstorming.

## Required outputs

Each session should produce:

- inner-world note
- research-world note
- bridge verdict
- experience-layer reflection
- product/test implication

## Evaluation criteria

Compare `Dream Then Test` against standard brainstorming on:

- originality
- non-generic specificity
- user ownership
- evidence calibration
- claim-status accuracy
- implementation usefulness
- privacy safety
- ability to preserve uncertainty

## Failure modes

- dream phase becomes unsupported certainty.
- research phase erases project-native insight.
- bridge rubber-stamps the preferred side.
- output becomes abstract but not buildable.
- experience-layer language inflates into false claims.
- citations become decoration instead of constraint.

## First experiment

Run the same MC concept through three workflows:

1. ordinary AI brainstorming
2. research-first synthesis
3. Dream Then Test

Blind compare the outputs for novelty, specificity, evidence discipline, and build-readiness.
